1. Java Core & OOP

1. JDK, JRE, JVM khác nhau thế nào?
  • JVM (Java Virtual Machine): máy ảo chạy bytecode (.class). Chịu trách nhiệm: load class, verify bytecode, thực thi, quản lý bộ nhớ (Heap/Stack), Garbage Collection. JVM là đặc tả — mỗi HĐH có implementation riêng (HotSpot, OpenJ9). Nhờ JVM mà Java "write once, run anywhere".
  • JRE (Java Runtime Environment) = JVM + thư viện chuẩn (rt.jar, java.base) + file cấu hình. Chỉ đủ để chạy ứng dụng Java, không biên dịch được.
  • JDK (Java Development Kit) = JRE + công cụ dev: javac (compiler), jar, javadoc, jdb (debugger), jps, jstat. Cần JDK để phát triển.

Mối quan hệ: JDK ⊃ JRE ⊃ JVM.

Đừng nhầm: máy chỉ cần JRE để chạy app; dev cần JDK. Từ Java 11, Oracle không còn phát hành JRE riêng — JDK đã bao gồm.
2. OOP có mấy tính chất? Cho ví dụ.

4 tính chất:

  1. Encapsulation (Đóng gói): che giấu state, chỉ expose qua method. Ví dụ private double balance; + getBalance() / deposit(). Lợi ích: kiểm soát truy cập, dễ bảo trì.
  2. Inheritance (Kế thừa): class con tái sử dụng code class cha. Ví dụ Dog extends Animal. Lợi ích: DRY, mở rộng dễ.
  3. Polymorphism (Đa hình): cùng method, nhiều hành vi. Gồm compile-time (overloading) và runtime (overriding). Ví dụ Animal a = new Dog(); a.sound(); → gọi Dog.sound().
  4. Abstraction (Trừu tượng): ẩn chi tiết cài đặt, chỉ lộ interface. Ví dụ interface PaymentService { void pay(); } — client chỉ biết pay(), không quan tâm VNPay/MoMo bên dưới.
Phỏng vấn hay hỏi kèm: "Cho ví dụ thực tế trong dự án em?" — nên chuẩn bị 1 ví dụ cụ thể (ví dụ: tầng Service dùng interface để đa hình giữa nhiều implementation).
3. Abstract class vs Interface? Khi nào dùng?

Abstract class:

  • Có thể chứa field (state), constructor, method có/không có thân.
  • Class con dùng extends, chỉ kế thừa 1 class.
  • Dùng khi các class con chia sẻ code + state chung và có quan hệ "is-a" rõ ràng (ví dụ AbstractShape có color + draw() abstract).

Interface:

  • Java 8+: có default và static method; Java 9+: private method.
  • Field mặc định là public static final.
  • Class dùng implements, có thể implement nhiều interface → đa kế thừa kiểu.
  • Dùng khi muốn định nghĩa hợp đồng hành vi, cho phép nhiều class không liên quan cùng implement (ví dụ Comparable, Serializable).

Quy tắc chọn: Nếu cần state/constructor/versioning → abstract class. Nếu chỉ định nghĩa capability → interface. Trong Spring, hầu hết Service/Repository đều dùng interface để dễ mock test.

Java 8 ra đời default method làm interface gần giống abstract class, nhưng khác biệt cốt lõi vẫn là: state và đa kế thừa.
4. Overloading vs Overriding?

Overloading (compile-time / static polymorphism):

  • Cùng tên method, khác signature (số lượng, kiểu, thứ tự tham số).
  • Có thể cùng class hoặc class con.
  • Return type không tính vào signature → không thể overload chỉ bằng return type.
  • Ví dụ: add(int a, int b) và add(double a, double b).

Overriding (runtime / dynamic polymorphism):

  • Class con viết lại method của cha với cùng signature.
  • Quy tắc: access modifier không được thu hẹp, không throws checked exception rộng hơn, return type có thể là covariant (kiểu con).
  • Dùng @Override để compiler kiểm tra.

Overriding quyết định lúc runtime (dynamic dispatch), overloading quyết định lúc compile-time.

5. static, final, finally, finalize khác nhau?
  • static: thuộc về class chứ không phải instance. Có thể áp dụng cho: field, method, block, nested class. Static method không truy cập được non-static member. Static block chạy 1 lần khi class load.
  • final: biến không gán lại được; method không cho override; class không cho kế thừa (ví dụ String, Integer).
  • finally: block trong try-catch, luôn chạy dù có exception hay không (trừ khi JVM bị kill / System.exit()). Dùng để giải phóng resource. Từ Java 7 có try-with-resources thay thế.
  • finalize(): method được GC gọi trước khi thu hồi object. Deprecated từ Java 9, bỏ hẳn Java 18. Không nên dùng vì không đảm bảo thời điểm gọi, ảnh hưởng performance.
Phỏng vấn hay hỏi: "finally có luôn chạy không?" → Có, trừ khi JVM exit hoặc thread bị kill. Nếu trong try có return, finally vẫn chạy trước khi return.
6. == vs equals()? Contract equals/hashCode?

==: với primitive so sánh giá trị; với object so sánh địa chỉ vùng nhớ (reference).

equals(): mặc định của Object cũng so sánh reference, nhưng các class như String, Integer đã override để so sánh nội dung. Muốn so sánh đúng cho class tự định nghĩa → phải override.

Contract giữa equals() và hashCode():

  1. Nếu a.equals(b) là true → a.hashCode() == b.hashCode() bắt buộc.
  2. Ngược lại không bắt buộc: hashCode bằng nhau chưa chắc equals (do collision).
  3. Nếu không tuân thủ → HashMap, HashSet sẽ hoạt động sai (không tìm thấy key).
@Override public boolean equals(Object o) {
  if (this == o) return true;
  if (!(o instanceof User u)) return false;
  return Objects.equals(id, u.id) && Objects.equals(email, u.email);
}
@Override public int hashCode() { return Objects.hash(id, email); }
Phỏng vấn kinh điển: "Nếu override equals mà không override hashCode thì sao?" → HashMap/HashSet có thể mất key (vì bucket khác nhau).
7. Immutable class là gì? Cách tạo?

Immutable class = object không thể thay đổi state sau khi tạo. Mọi thao tác "sửa" đều trả về object mới.

Cách tạo:

  1. Khai báo class final (không cho kế thừa — tránh subclass phá vỡ tính immutable).
  2. Tất cả field private final.
  3. Không có setter.
  4. Khởi tạo giá trị qua constructor, deep copy với field mutable (List, Date, array).
  5. Getter trả về defensive copy với field mutable.
public final class Money {
  private final BigDecimal amount;
  private final List<String> tags;

  public Money(BigDecimal amount, List<String> tags) {
    this.amount = amount;
    this.tags = List.copyOf(tags); // defensive copy
  }
  public List<String> getTags() { return tags; } // List.copyOf đã immutable
}

Lợi ích: thread-safe tự nhiên (không cần synchronize), dễ cache, dễ làm key của HashMap, dễ reasoning.

Ví dụ class có sẵn: String, Integer, LocalDate, BigDecimal. Java 16+ có record giúp tạo nhanh immutable class.

8. String vs StringBuilder vs StringBuffer?
  • String: immutable. Mọi phép nối (+) tạo object mới. Với vòng lặp lớn → tạo nhiều object → GC pressure. Có String Pool để tái sử dụng literal.
  • StringBuilder: mutable, không thread-safe, nhanh nhất. Dùng khi thao tác trong 1 thread (phổ biến nhất).
  • StringBuffer: mutable, thread-safe (mọi method synchronized), chậm hơn StringBuilder. Chỉ dùng khi thực sự đa luồng.
// String trong vòng lặp → chậm
String s = "";
for (int i = 0; i < 10000; i++) s += i; // tạo 10000 object

// StringBuilder → nhanh
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 10000; i++) sb.append(i);

String Pool: literal như "abc" được lưu trong pool. "abc" == "abc" → true. Nhưng new String("abc") == "abc" → false.

Câu hỏi liên quan: "Vì sao String immutable?" → Để an toàn khi dùng làm key HashMap, thread-safe, cache được, bảo mật (password, URL), và tối ưu String Pool.
9. ArrayList vs LinkedList? HashMap vs HashSet?

ArrayList vs LinkedList: ArrayList dùng mảng động — get(i) O(1), thêm/xóa giữa O(n). LinkedList dùng doubly linked list — get(i) O(n), thêm/xóa đầu O(1), tốn bộ nhớ hơn (2 pointer/node). 90% trường hợp dùng ArrayList; LinkedList chỉ hữu ích khi thao tác ở đầu hoặc dùng làm Deque/Queue.

HashMap vs HashSet:

  • HashMap<K,V>: lưu key-value. Key unique, value có thể trùng.
  • HashSet<E>: chỉ lưu value, không trùng. Bên trong dùng HashMap với value là dummy object PRESENT.
  • Vì vậy HashSet.add(e) = map.put(e, PRESENT), contains(e) = map.containsKey(e).
10. HashMap hoạt động như thế nào?

Cấu trúc: mảng bucket (Node<K,V>[] table). Mỗi bucket là linked list; từ Java 8, nếu bucket > 8 phần tử → chuyển thành red-black tree (O(log n) thay vì O(n)).

Các bước put(k,v):

  1. Tính hash = (h = k.hashCode()) ^ (h >>> 16) — trộn bit cao xuống thấp để phân tán đều.
  2. index = hash & (n - 1) với n là capacity (lũy thừa 2) — nhanh hơn modulo.
  3. Duyệt bucket: nếu key đã tồn tại (equals) → ghi đè value.
  4. Nếu chưa có → thêm node mới vào đầu/cuối list.
  5. Nếu size > capacity * loadFactor → resize gấp đôi (rehash toàn bộ).

Tham số mặc định: capacity = 16, loadFactor = 0.75. Ngưỡng resize = 12.

Collision handling: chaining (linked list). Nếu > 8 → treeify. Nếu < 6 → untreeify.

Vì sao capacity phải lũy thừa 2? Vì hash & (n-1) tương đương hash % n nhưng nhanh hơn nhiều, và chỉ đúng khi n là lũy thừa 2.
11. HashMap vs Hashtable vs ConcurrentHashMap?
  • HashMap: không thread-safe. Cho phép 1 null key và nhiều null value. Nhanh nhất.
  • Hashtable: legacy (từ Java 1.0). Mọi method synchronized → thread-safe nhưng chậm. Không cho null key/value. Hầu như không dùng nữa.
  • ConcurrentHashMap: thread-safe nhưng hiệu năng cao. Java 7 dùng segmented lock (16 segment); Java 8+ dùng CAS + synchronized trên từng bucket. Cho phép đọc song song, ghi lock cục bộ → nhanh hơn Hashtable nhiều. Không cho null key/value (tránh ambiguity khi get trả null).
Map<String, Integer> map = new ConcurrentHashMap<>();
map.computeIfAbsent("a", k -> 1); // atomic
Điểm cộng khi phỏng vấn: nói được "Java 8 thay segment lock bằng CAS + synchronized trên bucket, nên đọc gần như lock-free".
12. Generics? Wildcard ? extends / ? super?

Generics cho phép type-safe lúc compile, tránh cast. Ví dụ List<String> chỉ chứa String.

Type Erasure: generic bị xóa lúc runtime → List<String> và List<Integer> đều là List. Vì vậy không thể new T() hay T.class trực tiếp.

Wildcard:

  • ? extends T: producer — chỉ đọc được (không add, trừ null). Ví dụ List<? extends Number> đọc được Number.
  • ? super T: consumer — chỉ ghi được. Ví dụ List<? super Integer> add được Integer.
  • ? (unbounded): chỉ đọc được Object.

PECS: Producer Extends, Consumer Super.

static <T> void copy(List<? extends T> src, List<? super T> dst) {
  for (T t : src) dst.add(t);
}
13. Checked vs Unchecked exception? try-with-resources?

Checked exception: kế thừa Exception (không phải RuntimeException). Ví dụ: IOException, SQLException. Compiler bắt buộc phải try-catch hoặc khai báo throws. Dùng khi caller có thể recover (retry, thông báo user).

Unchecked exception: kế thừa RuntimeException. Ví dụ: NullPointerException, IllegalArgumentException. Không bắt buộc xử lý. Thường là lỗi lập trình, không recover được.

try-with-resources (Java 7+): tự động đóng resource implements AutoCloseable.

try (BufferedReader br = new BufferedReader(new FileReader("f.txt"))) {
  return br.readLine();
} // br.close() tự gọi, kể cả khi có exception

Multi-catch (Java 7+): catch (IOException | SQLException e) { ... }.

Trong Spring, hầu hết exception trong service nên là unchecked (RuntimeException) để @Transactional rollback mặc định, và dùng @RestControllerAdvice để xử lý tập trung.
14. Java 8 có gì mới?

Bản release lớn nhất của Java, đưa vào functional programming:

  • Lambda expression: (a, b) -> a + b — viết gọn anonymous class.
  • Functional interface: interface có đúng 1 abstract method, có @FunctionalInterface. Ví dụ: Function, Predicate, Supplier, Consumer.
  • Stream API: xử lý collection theo pipeline: filter, map, reduce, collect, flatMap. Hỗ trợ parallelStream.
  • Optional: tránh NullPointerException bằng cách biểu diễn "có thể null".
  • Default & static method trong interface.
  • Method reference: String::length, System.out::println.
  • java.time API: LocalDate, LocalDateTime, ZonedDateTime, Duration, Period — immutable, thread-safe (thay thế Date/Calendar cũ).
  • Metaspace thay PermGen.
Phỏng vấn hay yêu cầu ví dụ Stream: cho list User, lọc tuổi > 18, map sang tên, sort, collect thành List.
15. Java 11/17 có gì đáng chú ý?

Java 11 (LTS 2018):

  • var dùng được trong lambda: (var a, var b) -> a + b.
  • HTTP Client mới (java.net.http) hỗ trợ async, HTTP/2, WebSocket.
  • Bỏ Java EE và CORBA modules.
  • Method String mới: isBlank(), lines(), strip(), repeat().
  • Chạy file .java trực tiếp không cần compile: java Hello.java.

Java 17 (LTS 2021):

  • Records: record Point(int x, int y) {} — tự sinh constructor, getter, equals, hashCode, toString. Dùng cho DTO/immutable data.
  • Sealed classes: sealed interface Shape permits Circle, Square {} — kiểm soát class nào được kế thừa.
  • Pattern matching instanceof: if (o instanceof User u) { u.getName(); } — không cần cast.
  • Text block: """...""" — viết multi-line string gọn hơn.
  • Switch expression: var x = switch(day) { case MON -> 1; ... };.
  • Bỏ Nashorn, Applet API, Security Manager (deprecated).
Spring Boot 3.x bắt buộc Java 17+. Nếu công ty dùng Boot 3, chắc chắn sẽ bị hỏi về record, sealed class.
16. Thread, Runnable, Callable?
  • Thread: class đại diện 1 luồng. Có 2 cách tạo: extends Thread hoặc implements Runnable. Ưu tiên Runnable vì không chiếm slot kế thừa.
  • Runnable: void run(). Không trả về kết quả, không throws checked exception.
  • Callable<V>: V call() throws Exception. Trả về kết quả, có thể throws. Dùng với ExecutorService.submit() → trả về Future<V>.
ExecutorService pool = Executors.newFixedThreadPool(4);
Future<Integer> f = pool.submit(() -> 1 + 1); // Callable
Integer result = f.get(); // block chờ kết quả

Thread lifecycle: NEW → RUNNABLE → (BLOCKED / WAITING / TIMED_WAITING) → TERMINATED.

Thực tế ít khi tạo Thread trực tiếp. Dùng ExecutorService, CompletableFuture, hoặc @Async của Spring.
17. synchronized vs volatile vs Atomic?
  • synchronized: khóa (monitor lock). Đảm bảo cả mutual exclusion (chỉ 1 thread vào tại một thời điểm) và visibility. Có thể áp dụng cho method hoặc block. Nhược điểm: chậm, có thể gây deadlock.
  • volatile: chỉ đảm bảo visibility — mọi write được flush xuống main memory, mọi read lấy từ main memory. Không đảm bảo atomic. Phù hợp cho flag boolean, trạng thái đơn giản.
  • Atomic classes (AtomicInteger, AtomicLong, AtomicReference): dùng CAS (Compare-And-Swap) — không lock, nhanh hơn synchronized. Đảm bảo atomic cho single variable.
// Sai: race condition
if (count < 10) count++;

// Đúng với Atomic
atomicCount.incrementAndGet(); // atomic
Điểm cộng: nói được volatile không đảm bảo atomic cho i++ (vì là 3 phép: read-modify-write).
18. ExecutorService, CompletableFuture?

ExecutorService: quản lý thread pool, tách việc tạo task và chạy task.

  • Executors.newFixedThreadPool(n): pool cố định.
  • Executors.newCachedThreadPool(): tạo thread khi cần, tái sử dụng.
  • Executors.newScheduledThreadPool(n): cho task định kỳ.
  • submit() trả Future, invokeAll() chờ tất cả.

CompletableFuture (Java 8+): pipeline async, không block.

CompletableFuture.supplyAsync(() -> callApiA())
  .thenApply(data -> transform(data))
  .thenCompose(x -> callApiB(x))
  .exceptionally(ex -> fallback())
  .thenAccept(System.out::println);

// Chạy song song và gộp
CompletableFuture.allOf(f1, f2, f3).join();

Các method hay dùng: thenApply (map), thenCompose (flatMap), thenCombine (gộp 2), allOf, anyOf, exceptionally, handle.

Trong Spring, tương đương là @Async trả về CompletableFuture.
19. Deadlock là gì? Cách phòng tránh?

Deadlock: 2+ thread chờ nhau giải phóng lock → tất cả bị treo mãi. Điều kiện Coffman (cần cả 4):

  1. Mutual exclusion: tài nguyên chỉ 1 thread dùng.
  2. Hold and wait: thread giữ lock và chờ lock khác.
  3. No preemption: không ai tước lock được.
  4. Circular wait: chu trình chờ.

Phòng tránh:

  • Lock theo thứ tự cố định (phá circular wait).
  • Dùng tryLock(timeout) thay vì lock() — nếu fail thì release và retry.
  • Giảm thời gian giữ lock, tránh nested lock.
  • Dùng java.util.concurrent (ConcurrentHashMap, Atomic) thay vì tự synchronize.
  • Phát hiện bằng jstack hoặc jconsole (báo "Found one Java-level deadlock").
20. JVM memory gồm những vùng nào?

Heap (chia sẻ giữa thread, GC quản lý):

  • Young Gen: Eden + 2 Survivor (S0, S1). Object mới sinh ra ở Eden.
  • Old Gen (Tenured): object sống lâu, sau nhiều lần Minor GC.
  • Minor GC (Young), Major/Full GC (Old).

Non-Heap:

  • Stack (per-thread): frame method, biến local, toán hạng. Tràn → StackOverflowError (đệ quy vô hạn).
  • Metaspace (Java 8+, thay PermGen): metadata class, method, hằng số.
  • PC Register: địa chỉ instruction hiện tại.
  • Native Method Stack: cho code native (JNI).

Nếu Heap đầy không GC được → OutOfMemoryError: Java heap space.

Tuning phổ biến: -Xms (heap ban đầu), -Xmx (heap tối đa), -Xss (stack size), -XX:MetaspaceSize.
21. Memory leak trong Java?

Xảy ra khi object không còn dùng nhưng vẫn được tham chiếu → GC không thu hồi → heap tăng dần → OutOfMemoryError.

Nguyên nhân phổ biến:

  • Static collection: static List<X> thêm mãi không xóa.
  • Listener/Callback không gỡ: đăng ký event listener nhưng không remove.
  • ThreadLocal không remove: trong thread pool, ThreadLocal giữ value suốt đời thread.
  • Cache không giới hạn: HashMap làm cache không có eviction → nên dùng Caffeine/Guava với maxSize.
  • Unclosed resources: Connection, InputStream không đóng.
  • Inner class không static giữ reference outer class.

Cách phát hiện: heap dump (jmap -dump), phân tích bằng Eclipse MAT / VisualVM, theo dõi GC log.

22. Serialization, transient?

Serialization: chuyển object → byte stream để lưu file, gửi mạng, cache (Redis), session clustering.

  • Class phải implements Serializable.
  • ObjectOutputStream.writeObject() và ObjectInputStream.readObject().
  • serialVersionUID: nên khai báo để kiểm soát version. Nếu không, JVM tự sinh — thay đổi class nhỏ cũng có thể gây InvalidClassException.

transient: đánh dấu field không được serialize. Ví dụ password, connection, derived field. Khi deserialize, field này sẽ là default value (null, 0).

public class User implements Serializable {
  private static final long serialVersionUID = 1L;
  private String username;
  private transient String password; // không serialize
}
Trong Spring Boot, DTO thường không cần Serializable trừ khi dùng session/cache. Nhưng entity JPA nên implement Serializable theo spec.

2. Spring Core

23. Spring là gì? Ưu điểm?

Spring là framework Java mã nguồn mở ra đời 2003, giải quyết vấn đề phức tạp của Java EE. Nó cung cấp hạ tầng để xây dựng ứng dụng: IoC container, DI, AOP, transaction, MVC, data access, security.

Ưu điểm:

  • Loose coupling nhờ DI — dễ test, dễ thay thế implementation.
  • POJO-based: không cần kế thừa class đặc biệt, code sạch.
  • Modular: dùng module nào cần module đó (spring-core, spring-web, spring-data...).
  • AOP giúp tách cross-cutting concern (logging, transaction, security).
  • Hệ sinh thái lớn: Spring Boot, Spring Cloud, Spring Security, Spring Data...
  • Cộng đồng khổng lồ, tài liệu phong phú, dễ tuyển dụng.
Đừng nói "Spring là framework để làm web" — sai. Spring core là IoC container; web chỉ là 1 module.
24. IoC và DI là gì?

IoC (Inversion of Control): "đảo ngược quyền điều khiển". Thay vì code tự tạo object (new UserService()), framework sẽ tạo và quản lý. Đây là nguyên lý; DI là cách thực hiện.

DI (Dependency Injection): tiêm dependency vào object. 3 kiểu:

  1. Constructor injection (khuyến nghị): field final, đảm bảo dependency không null, dễ test. Nếu chỉ có 1 constructor, không cần @Autowired.
  2. Setter injection: cho dependency optional, có thể thay đổi sau.
  3. Field injection: dùng @Autowired trên field — không khuyến nghị vì khó test, che giấu dependency.
@Service
@RequiredArgsConstructor // Lombok → tự sinh constructor
public class UserService {
  private final UserRepository repo;   // constructor injection
  private final EmailService email;
}
Phỏng vấn hay hỏi: "Vì sao constructor injection tốt hơn field injection?" → Vì field final (immutable), fail fast nếu thiếu bean, không cần reflection khi test, thể hiện rõ dependency.
25. Bean scope trong Spring?
  • singleton (mặc định): 1 instance duy nhất cho mỗi IoC container. Lưu ý: không nhầm với Singleton pattern GoF (per-JVM). Đây là per-container.
  • prototype: tạo instance mới mỗi lần getBean() hoặc inject. Spring không quản lý vòng đời destroy của prototype.
  • request: 1 instance cho mỗi HTTP request (chỉ web).
  • session: 1 instance cho mỗi HTTP session.
  • application: 1 instance cho ServletContext.
  • websocket: cho WebSocket session.

Đặt scope: @Scope("prototype") hoặc @RequestScope, @SessionScope.

Cảnh báo kinh điển: inject prototype bean vào singleton bean → prototype chỉ tạo 1 lần. Giải pháp: dùng ObjectProvider, @Lookup, hoặc ApplicationContext.getBean().
26. Bean lifecycle?

Vòng đời của một Spring bean (do BeanFactory quản lý):

  1. Instantiation: gọi constructor.
  2. Populate properties: inject dependency.
  3. Aware interfaces: BeanNameAware, BeanFactoryAware, ApplicationContextAware.
  4. BeanPostProcessor.postProcessBeforeInitialization.
  5. @PostConstruct (JSR-250).
  6. InitializingBean.afterPropertiesSet().
  7. init-method (XML hoặc @Bean(initMethod="...")).
  8. BeanPostProcessor.postProcessAfterInitialization → đây là chỗ AOP proxy được tạo.
  9. Bean sẵn sàng dùng.
  10. Khi container shutdown: @PreDestroy → DisposableBean.destroy() → destroy-method.
Thứ tự quan trọng: @PostConstruct chạy trước afterPropertiesSet(). Còn AOP proxy chỉ được tạo ở bước 8 — nghĩa là nếu bạn tự gọi method của chính mình trong @PostConstruct, annotation @Transactional sẽ không có tác dụng.
27. @Component vs @Service vs @Repository vs @Controller?

Về mặt kỹ thuật, cả 4 đều là specialization của @Component — đều được component scan tìm và tạo bean. Khác nhau ở ngữ nghĩa và xử lý bổ sung:

  • @Component: bean chung, không rõ tầng.
  • @Service: tầng business logic. Không có behavior đặc biệt, chỉ mang tính semantic.
  • @Repository: tầng DAO. Có behavior bổ sung: Spring tự động chuyển đổi exception của JPA/JDBC (như SQLException) sang DataAccessException (unchecked).
  • @Controller: MVC controller, hỗ trợ @RequestMapping. Được DispatcherServlet detect.

Ngoài ra @RestController = @Controller + @ResponseBody.

Câu hỏi mở rộng: "Nếu đổi @Service thành @Component có chạy không?" → Có, vì cả 2 đều là @Component. Nhưng đổi @Repository thành @Component → mất exception translation.
28. @Autowired vs @Qualifier vs @Primary vs @Resource?
  • @Autowired: inject theo type. Nếu có nhiều bean cùng type → lỗi NoUniqueBeanDefinitionException. Có thuộc tính required=false cho phép null.
  • @Qualifier("beanName"): chỉ định bean cụ thể khi có nhiều cùng type. Thường đi kèm @Autowired.
  • @Primary: đánh dấu 1 bean là ưu tiên khi có nhiều bean cùng type. Nếu vẫn còn ambiguous → dùng @Qualifier.
  • @Resource(name="..."): chuẩn JSR-250, inject theo name trước, nếu không có mới theo type. Thuộc Java EE, Spring hỗ trợ.
  • Ngoài ra: @Inject (JSR-330) tương đương @Autowired.
@Service
public class PaymentService {
  @Autowired @Qualifier("vnPayGateway")
  private PaymentGateway gateway;
}

@Primary @Component
public class MomoGateway implements PaymentGateway {}
29. @Configuration vs @Component? @Bean?
  • @Component: class thường, được scan và tạo bean. Nhưng nếu trong class có method @Bean gọi nhau, mỗi lần gọi có thể tạo instance mới.
  • @Configuration: đặc biệt — Spring dùng CGLIB proxy để đảm bảo method @Bean gọi lẫn nhau luôn trả về cùng 1 bean (singleton).
  • @Bean: khai báo bean thủ công cho class không có annotation Spring (thư viện bên thứ 3, JDK class).
@Configuration
public class AppConfig {
  @Bean
  public ObjectMapper objectMapper() { return new ObjectMapper(); }

  @Bean
  public RestTemplate restTemplate(ObjectMapper om) { // inject bean trên
    RestTemplate rt = new RestTemplate();
    rt.setMessageConverters(...);
    return rt;
  }
}

Có thể dùng @Configuration(proxyBeanMethods = false) để tắt CGLIB proxy — nhanh hơn nếu không cần đảm bảo singleton giữa các method @Bean. Spring Boot 2+ dùng cách này cho auto-config.

30. AOP là gì?

AOP (Aspect-Oriented Programming): tách các cross-cutting concern (logging, transaction, security, cache) ra khỏi business logic.

Khái niệm:

  • Aspect: module chứa logic cross-cutting.
  • JoinPoint: điểm có thể chèn advice — trong Spring chỉ hỗ trợ method execution.
  • Pointcut: biểu thức chọn joinpoint (ví dụ: execution(* com.example.service.*.*(..))).
  • Advice: hành động tại joinpoint: @Before, @AfterReturning, @AfterThrowing, @After, @Around (mạnh nhất — có thể thay đổi return, catch exception).
  • Weaving: Spring dùng proxy-based (JDK dynamic proxy cho interface, CGLIB cho class).
@Aspect @Component
public class LoggingAspect {
  @Around("execution(* com.example.service.*.*(..))")
  public Object log(ProceedingJoinPoint pjp) throws Throwable {
    long start = System.currentTimeMillis();
    Object result = pjp.proceed();
    System.out.println(pjp.getSignature() + " took " + (System.currentTimeMillis() - start) + "ms");
    return result;
  }
}
Đây là nền tảng của @Transactional, @Cacheable, @Async, Spring Security. Hiểu AOP = hiểu vì sao @Transactional không hoạt động khi gọi internal method.
31. Spring MVC flow?

Luồng request trong Spring MVC:

  1. Client gửi HTTP request.
  2. DispatcherServlet (Front Controller) nhận, tra cứu HandlerMapping để tìm Controller phù hợp.
  3. Nếu có Interceptor → chạy preHandle.
  4. HandlerAdapter gọi method controller. Trong quá trình: convert request param, bind @RequestBody, validate @Valid.
  5. Controller gọi Service, xử lý, trả về ModelAndView (view) hoặc object (REST).
  6. Interceptor postHandle → afterCompletion.
  7. Với REST: HttpMessageConverter (Jackson) chuyển object → JSON.
  8. Với MVC: ViewResolver tìm view (JSP, Thymeleaf) → render.
  9. Response trả về client.
Điểm phỏng vấn: DispatcherServlet là Front Controller, được Spring Boot auto-config qua DispatcherServletAutoConfiguration.
32. @Controller vs @RestController?

@RestController = @Controller + @ResponseBody ở cấp class.

  • @Controller: method trả về view name, ViewResolver sẽ render (JSP, Thymeleaf). Muốn trả JSON thì phải thêm @ResponseBody trên từng method.
  • @RestController: mọi method trả về JSON/XML trực tiếp. Dùng cho REST API.

Bên dưới, @ResponseBody khiến Spring dùng HttpMessageConverter (Jackson) để convert thay vì ViewResolver.

33. Annotation REST thường dùng?
  • @RequestMapping: mapping URL (dùng cho cả class). Có thể chỉ định method, consumes, produces.
  • @GetMapping, @PostMapping, @PutMapping, @PatchMapping, @DeleteMapping: shortcut của @RequestMapping(method=...).
  • @PathVariable: lấy biến từ URL path: /users/{id}.
  • @RequestParam: query param: ?page=0&size=10.
  • @RequestBody: bind JSON body thành object.
  • @ResponseBody: trả object → JSON.
  • @ResponseStatus: set HTTP status code trả về.
  • @ResponseEntity: trả về body + status + headers linh hoạt.
@GetMapping("/users/{id}")
public ResponseEntity<UserDto> get(@PathVariable Long id,
                                    @RequestParam(defaultValue = "vi") String lang) {
  return ResponseEntity.ok(service.findById(id));
}
34. Xử lý exception toàn cục?

Dùng @RestControllerAdvice (kết hợp @ControllerAdvice + @ResponseBody) để bắt exception toàn cục.

@RestControllerAdvice
public class GlobalExceptionHandler {

  @ExceptionHandler(ResourceNotFoundException.class)
  @ResponseStatus(HttpStatus.NOT_FOUND)
  public ErrorResponse notFound(ResourceNotFoundException ex) {
    return new ErrorResponse("NOT_FOUND", ex.getMessage());
  }

  @ExceptionHandler(MethodArgumentNotValidException.class)
  @ResponseStatus(HttpStatus.BAD_REQUEST)
  public ErrorResponse validation(MethodArgumentNotValidException ex) {
    String msg = ex.getBindingResult().getFieldErrors().stream()
        .map(e -> e.getField() + ": " + e.getDefaultMessage())
        .collect(Collectors.joining(", "));
    return new ErrorResponse("VALIDATION_ERROR", msg);
  }

  @ExceptionHandler(Exception.class)
  @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR)
  public ErrorResponse fallback(Exception ex) {
    return new ErrorResponse("INTERNAL_ERROR", "Unexpected error");
  }
}

Thứ tự ưu tiên: handler cụ thể > handler cha (ví dụ Exception.class là fallback).

35. Validation với @Valid?

Spring Boot hỗ trợ Bean Validation (JSR-380) qua Hibernate Validator. Cần dependency spring-boot-starter-validation.

public class UserRequest {
  @NotBlank(message = "Name required")
  @Size(min = 2, max = 50)
  private String name;

  @Email @NotBlank
  private String email;

  @Min(18) @Max(120)
  private int age;

  @Pattern(regexp = "^\\+?[0-9]{10,15}$")
  private String phone;
}

@PostMapping
public ResponseEntity<UserDto> create(@Valid @RequestBody UserRequest req) { ... }

Các annotation phổ biến: @NotNull, @NotBlank (khác với @NotEmpty — chỉ check space), @Size, @Min, @Max, @Email, @Pattern, @Positive, @Past, @Future.

Custom validator: implement ConstraintValidator<A, T>.

36. Filter vs Interceptor vs AOP?
  • Filter: thuộc Servlet container (Tomcat). Chạy trước DispatcherServlet, xử lý request/response thô. Dùng cho: CORS, encoding, logging request, authentication cơ bản. Đăng ký qua @WebFilter hoặc FilterRegistrationBean.
  • Interceptor: thuộc Spring MVC. Chạy sau DispatcherServlet, trước/sau Controller. Có preHandle, postHandle, afterCompletion. Có thể truy cập HandlerMethod. Đăng ký qua WebMvcConfigurer.addInterceptors.
  • AOP: ở tầng method, dùng proxy. Chạy bên trong Service/Repository. Không có khái niệm HTTP request/response. Dùng cho: transaction, logging business, security.

Thứ tự: Filter → DispatcherServlet → Interceptor.preHandle → AOP around → Controller → AOP → Interceptor.postHandle → Filter.

37. Authentication vs Authorization?
  • Authentication (xác thực): "Bạn là ai?" — kiểm tra username/password, token, session. Kết quả: danh tính (Principal). Nếu fail → 401 Unauthorized.
  • Authorization (phân quyền): "Bạn được làm gì?" — kiểm tra role/permission. Nếu fail → 403 Forbidden.

Trong Spring Security:

  • Authentication: AuthenticationManager, UserDetailsService, AuthenticationProvider.
  • Authorization: authorizeHttpRequests, @PreAuthorize, @Secured, @RolesAllowed.
401 = chưa xác thực; 403 = đã xác thực nhưng không có quyền. Nhiều bạn nhầm 2 cái này.
38. JWT là gì? Luồng xác thực?

JWT (JSON Web Token) = chuỗi gồm 3 phần, cách nhau bởi dấu .:

  • Header (base64): {"alg":"HS256","typ":"JWT"}.
  • Payload (base64): claims — sub (subject), exp (expiration), iat, custom claims (role, userId).
  • Signature: HMACSHA256(base64(header) + "." + base64(payload), secret) — đảm bảo token không bị sửa.

Lưu ý: payload chỉ base64, không mã hóa → không lưu thông tin nhạy cảm.

Luồng xác thực:

  1. Client POST /login với username/password.
  2. Server verify → tạo JWT (access token + refresh token), trả về client.
  3. Client lưu token (memory/localStorage/cookie httpOnly).
  4. Mỗi request gửi header Authorization: Bearer <token>.
  5. Server filter (JwtFilter) verify signature + exp → set SecurityContext.
  6. Nếu hợp lệ → cho vào controller; ngược lại → 401.
  7. Khi access token hết hạn, client dùng refresh token để lấy token mới.
Ưu điểm JWT: stateless, scale ngang dễ. Nhược điểm: không revoke được dễ dàng (phải blacklist hoặc dùng refresh token rotation).
39. BCryptPasswordEncoder?

BCrypt là thuật toán hash mật khẩu có 2 đặc điểm quan trọng:

  • Salt tự động: mỗi lần hash sinh salt ngẫu nhiên → cùng password cho hash khác nhau. Chống rainbow table.
  • Chậm có chủ đích: cost factor (mặc định 10) — hash 2^10 vòng. Chống brute force.
@Bean PasswordEncoder passwordEncoder() {
  return new BCryptPasswordEncoder(12); // cost 12, chậm hơn nhưng an toàn hơn
}

// Khi đăng ký:
String hash = encoder.encode("rawPassword");

// Khi login:
boolean ok = encoder.matches("rawPassword", hash);

So sánh: MD5/SHA-1 không dùng cho password (nhanh, không salt). Argon2 mạnh hơn BCrypt nhưng BCrypt vẫn là lựa chọn phổ biến.

3. Spring Boot

40. Spring Boot là gì? Khác Spring MVC?

Spring Boot là lớp trên Spring, giải quyết vấn đề "configuration hell" của Spring truyền thống. Mục tiêu: convention over configuration — chạy app chỉ với 1 file main.

Đặc điểm:

  • Auto-configuration: tự cấu hình bean dựa trên classpath.
  • Starter dependencies: nhóm dependency theo tính năng.
  • Embedded server: Tomcat/Jetty sẵn trong jar → chạy bằng java -jar.
  • Production-ready: Actuator, metrics, health check.
  • Không cần XML: cấu hình hoàn toàn bằng annotation + properties.

Khác Spring MVC: Spring MVC chỉ là module web của Spring, cần cấu hình thủ công (web.xml, DispatcherServlet, ViewResolver...). Spring Boot tự động hóa hết.

41. @SpringBootApplication gồm gì?

@SpringBootApplication là meta-annotation gồm 3 annotation:

  1. @SpringBootConfiguration: kế thừa @Configuration, đánh dấu class là config chính.
  2. @EnableAutoConfiguration: bật auto-configuration — Spring Boot quét classpath và tự cấu hình bean.
  3. @ComponentScan: scan các @Component, @Service... trong package hiện tại và sub-package.
@SpringBootApplication
public class Application {
  public static void main(String[] args) {
    SpringApplication.run(Application.class, args);
  }
}
Vì @ComponentScan mặc định quét package chứa class main, nên class Application phải ở package gốc (root), các package con nằm dưới.
42. Auto-configuration hoạt động thế nào?

Cơ chế:

  1. @EnableAutoConfiguration import AutoConfigurationImportSelector.
  2. Selector đọc file META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports (Boot 2.7+/3.x) hoặc spring.factories (Boot 2.6 trở về trước) — chứa danh sách auto-config class.
  3. Mỗi auto-config class có các annotation điều kiện: @ConditionalOnClass, @ConditionalOnMissingBean, @ConditionalOnProperty, @ConditionalOnWebApplication.
  4. Các auto-config thoả điều kiện sẽ tạo bean (DataSource, EntityManager, DispatcherServlet...).

Ví dụ: có spring-boot-starter-data-jpa + có DataSource trong config → JpaAutoConfiguration tự tạo EntityManagerFactory, TransactionManager.

Debug: chạy với --debug để xem báo cáo auto-config (positive/negative matches).

43. Starter dependency?

Starter là POM tổng hợp, kéo theo nhiều dependency liên quan, đảm bảo version tương thích.

Phổ biến:

  • spring-boot-starter-web: Spring MVC + Tomcat + Jackson.
  • spring-boot-starter-data-jpa: JPA + Hibernate + HikariCP.
  • spring-boot-starter-security: Spring Security.
  • spring-boot-starter-validation: Hibernate Validator.
  • spring-boot-starter-actuator: health, metrics, info.
  • spring-boot-starter-test: JUnit 5, Mockito, AssertJ.
  • spring-boot-starter-cache: cache abstraction.
  • spring-boot-starter-data-redis: Redis (Lettuce).
  • spring-boot-starter-amqp: RabbitMQ.
  • spring-boot-starter-webflux: reactive web (Netty).
Đừng quên nói về spring-boot-dependencies (BOM) quản lý version — bạn không cần khai báo version cho từng starter.
44. Embedded server là gì?

Spring Boot nhúng sẵn server (Tomcat mặc định) vào trong jar. Không cần deploy WAR lên server ngoài.

  • Chạy: java -jar myapp.jar → server khởi động, app chạy trên port 8080.
  • Đổi server: loại spring-boot-starter-tomcat, thêm spring-boot-starter-jetty hoặc spring-boot-starter-undertow.
  • Cấu hình: server.port=8081, server.servlet.context-path=/api, server.ssl.enabled=true.
  • Tắt hoàn toàn web: spring.main.web-application-type=none.
Deploy lên môi trường có server sẵn (như nhúng vào WildFly)? Đổi packaging thành war, extends SpringBootServletInitializer. Nhưng microservices thường chạy jar.
45. application.properties vs yml? Profile?

Cả hai tương đương về chức năng, chỉ khác cú pháp. YAML có cấu trúc phân cấp, dễ đọc khi config nhiều.

# application.properties
spring.datasource.url=jdbc:mysql://localhost:3306/db
spring.datasource.username=root

# application.yml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/db
    username: root

Profile: chia config theo môi trường.

  • application.yml — config chung.
  • application-dev.yml, application-prod.yml — override theo profile.
  • Chạy: java -jar app.jar --spring.profiles.active=prod hoặc set env var SPRING_PROFILES_ACTIVE=prod.
  • Trong code: @Profile("dev") trên class/method bean để chỉ load theo profile.

Thứ tự ưu tiên (cao → thấp): command line args → env var → application-{profile}.yml → application.yml → default.

46. Actuator là gì?

Actuator cung cấp các endpoint HTTP để giám sát và quản lý app production:

  • /actuator/health: trạng thái (UP/DOWN) — dùng cho load balancer, k8s probe.
  • /actuator/info: thông tin build (version, git commit).
  • /actuator/metrics: metrics (JVM, HTTP, DB pool).
  • /actuator/env, /actuator/configprops: config hiện tại.

  • /actuator/threaddump, /actuator/heapdump: debug.

Mặc định chỉ health và info được expose qua HTTP. Mở thêm:

management.endpoint.health.show-details=always
Phỏng vấn: "Bảo mật Actuator thế nào?" → Restrict access bằng Spring Security, đặt trên management port riêng management.server.port.
47. DevTools?

Spring Boot DevTools giúp tăng tốc development:

  • Automatic restart: khi code thay đổi, app tự restart (nhanh hơn restart thủ công nhờ 2 classloader: base + restart).

  • Tắt template cache: Thymeleaf/Freemarker render ngay khi sửa.

48. Cấu trúc REST CRUD?

Cấu trúc phân lớp chuẩn:

  • Controller: nhận HTTP request, validate, map sang DTO. Không chứa business logic.
  • Service: business logic, transaction, gọi Repository.
  • Repository: truy cập DB (JpaRepository).
  • Entity: đại diện bảng DB. Không expose ra API.
  • DTO: request/response object. Tách biệt với entity.
  • Mapper: convert Entity ↔ DTO (MapStruct, ModelMapper, hoặc thủ công).
  • Exception handler: @RestControllerAdvice.
@RestController
@RequestMapping("/api/users")
@RequiredArgsConstructor
public class UserController {
  private final UserService service;

  @GetMapping
  public List<UserDto> all() { return service.findAll(); }

  @GetMapping("/{id}")
  public UserDto one(@PathVariable Long id) { return service.findById(id); }

  @PostMapping
  @ResponseStatus(HttpStatus.CREATED)
  public UserDto create(@Valid @RequestBody UserRequest req) { return service.create(req); }

  @PutMapping("/{id}")
  public UserDto update(@PathVariable Long id, @Valid @RequestBody UserRequest req) {
    return service.update(id, req);
  }

  @DeleteMapping("/{id}")
  @ResponseStatus(HttpStatus.NO_CONTENT)
  public void delete(@PathVariable Long id) { service.delete(id); }
}
Điểm cộng: nhắc đến việc dùng DTO thay vì expose entity — tránh lộ DB schema, tránh vòng lặp JSON, dễ versioning.

50. @Scheduled?

Chạy method định kỳ. Cần bật @EnableScheduling ở class config.

@Component
public class JobScheduler {
  @Scheduled(fixedRate = 60000) // mỗi 60s, tính từ lúc bắt đầu
  public void job1() {}

  @Scheduled(fixedDelay = 60000) // 60s sau khi job trước xong
  public void job2() {}

  @Scheduled(cron = "0 0 2 * * *") // 2h sáng mỗi ngày
  public void cleanup() {}
}

Cron 6 field: second minute hour day-of-month month day-of-week.

  • *: mọi giá trị.
  • ?: không xác định.
  • */5: mỗi 5 đơn vị.
  • MON-FRI: khoảng.

Multi-instance: nếu deploy nhiều instance, job sẽ chạy trùng trên mọi instance. Giải pháp: dùng ShedLock, Quartz cluster, hoặc external scheduler.

Mặc định @Scheduled chạy trên 1 thread đơn → job chậm block job sau. Cấu hình pool: spring.task.scheduling.pool.size=5.
51. @Async?

Chạy method trên thread khác, trả về ngay cho caller. Cần @EnableAsync.

@Configuration
@EnableAsync
public class AsyncConfig {
  @Bean(name = "taskExecutor")
  public Executor taskExecutor() {
    ThreadPoolTaskExecutor exec = new ThreadPoolTaskExecutor();
    exec.setCorePoolSize(5);
    exec.setMaxPoolSize(20);
    exec.setQueueCapacity(100);
    exec.setThreadNamePrefix("async-");
    exec.initialize();
    return exec;
  }
}

@Service
public class EmailService {
  @Async("taskExecutor")
  public CompletableFuture<Void> sendEmail(String to) {
    // chạy background
    return CompletableFuture.completedFuture(null);
  }
}

Lưu ý: method phải public, không gọi từ chính class đó. Return type: void hoặc CompletableFuture<T>. Exception trong async method không tự propagate — cần AsyncUncaughtExceptionHandler.

52. Cache với @Cacheable?

Spring Cache abstraction. Bật @EnableCaching, dùng các annotation:

  • @Cacheable: nếu có trong cache → trả về; nếu không → chạy method, lưu cache.
  • @CachePut: luôn chạy method và cập nhật cache (dùng cho update).
  • @CacheEvict: xóa cache (dùng cho delete, hoặc allEntries=true xóa hết).
  • @Caching: gộp nhiều operation.
@Cacheable(value = "users", key = "#id")
public UserDto findById(Long id) { ... }

@CacheEvict(value = "users", key = "#id")
public void update(Long id, UserRequest req) { ... }

Provider: ConcurrentMapCache (default, dev), Caffeine (in-memory, tốt cho 1 instance), Redis (distributed).

spring.cache.type=redis
spring.redis.host=localhost
Cảnh báo: @Cacheable cũng bị ảnh hưởng bởi self-invocation. Và nhớ TTL cho Redis cache — nếu không, cache cũ sẽ tồn tại mãi.
53. Upload file? 
@PostMapping(value = "/upload", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
public ResponseEntity<String> upload(@RequestParam("file") MultipartFile file) throws IOException {
  if (file.isEmpty()) throw new BadRequestException("File empty");

  String contentType = file.getContentType();
  if (!List.of("image/png", "image/jpeg").contains(contentType))
    throw new BadRequestException("Only PNG/JPEG allowed");

  String fileName = UUID.randomUUID() + "_" + file.getOriginalFilename();
  Path path = Path.of("uploads", fileName);
  Files.createDirectories(path.getParent());
  file.transferTo(path);

  return ResponseEntity.ok("/files/" + fileName);
}

Cấu hình giới hạn trong application.yml:

spring:
  servlet:
    multipart:
      max-file-size: 5MB
      max-request-size: 10MB

Production: không lưu file vào filesystem server — dùng S3/MinIO (object storage). Dùng presigned URL để client upload trực tiếp.

54. CORS? CSRF?

CORS (Cross-Origin Resource Sharing): browser chặn request cross-origin mặc định. Server phải trả header Access-Control-Allow-Origin để cho phép.

@Configuration
public class CorsConfig implements WebMvcConfigurer {
  @Override public void addCorsMappings(CorsRegistry reg) {
    reg.addMapping("/api/**")
       .allowedOrigins("https://myapp.com")
       .allowedMethods("GET","POST","PUT","DELETE")
       .allowCredentials(true);
  }
}

CSRF (Cross-Site Request Forgery): kẻ tấn công lừa user đã login thực hiện request ngoài ý muốn.

  • Với app dùng session/cookie: nên bật CSRF protection.
  • Với REST API dùng JWT trong header Authorization: tắt CSRF vì attacker không đọc được token từ domain khác.

4. JPA / Hibernate / Database

56. JPA vs Hibernate vs JDBC?
  • JDBC: API Java chuẩn để kết nối DB. Viết SQL thủ công, tự quản lý Connection, PreparedStatement, ResultSet. Nhiều boilerplate.
  • JPA (Java Persistence API): specification (chuẩn) cho ORM — định nghĩa annotation, interface, cách map object ↔ table. Không phải implementation.
  • Hibernate: implementation phổ biến nhất của JPA. Cũng có API riêng (Session, Criteria) ngoài JPA.
  • Ngoài ra có EclipseLink, OpenJPA cũng implement JPA.

JPA giúp: không cần viết SQL cho CRUD, map object tự động, cache, lazy loading, transaction. Nhưng: ẩn chi tiết (dễ sinh query kém), khó tối ưu cho query phức tạp.

Khi cần performance cao hoặc query cực phức tạp → cân nhắc JDBC (JdbcTemplate) hoặc native query.
57. JpaRepository vs CrudRepository vs PagingAndSorting?

Cả 3 là interface của Spring Data JPA, kế thừa nhau theo thứ tự:

  • CrudRepository<T, ID>: CRUD cơ bản — save, saveAll, findById, findAll, delete, count, existsById.
  • PagingAndSortingRepository: thêm findAll(Pageable), findAll(Sort).
  • JpaRepository<T, ID>: thêm flush(), saveAndFlush(), deleteAllInBatch(), getById(), getOne(). Dùng phổ biến nhất.

JpaRepository cũng kế thừa 2 cái trên. Trong thực tế, chỉ cần dùng JpaRepository.

Từ Spring Data 3.x, PagingAndSortingRepository không còn extends CrudRepository nữa (do trùng lặp), nhưng JpaRepository vẫn kế thừa cả 2.
58. Query method? @Query JPQL vs native?

Query method: Spring Data tự sinh query từ tên method. Quy tắc: findBy + Field + Operator + And/Or + Field.

List<User> findByName(String name);
List<User> findByNameAndAge(String name, int age);
List<User> findByAgeGreaterThan(int age);
Optional<User> findByEmailIgnoreCase(String email);
long countByStatus(Status status);
List<User> findTop10ByOrderByCreatedAtDesc();

@Query JPQL: truy vấn trên entity (không phải table).

@Query("SELECT u FROM User u WHERE u.email = :email AND u.status = :status")
Optional<User> findActiveByEmail(@Param("email") String e, @Param("status") Status s);

@Modifying @Transactional
@Query("UPDATE User u SET u.status = :status WHERE u.id IN :ids")
int updateStatus(@Param("ids") List<Long> ids, @Param("status") Status s);

Native query: SQL thật, chạy trực tiếp DB.

@Query(value = "SELECT * FROM users WHERE LOWER(name) LIKE LOWER(CONCAT('%', :kw, '%'))",
       nativeQuery = true)
List<User> search(@Param("kw") String kw);
59. Persistence context?

Persistence Context là "cache tầng 1" của EntityManager, quản lý tập entity trong 1 transaction.

4 trạng thái của entity:

  • Transient (new): mới new User(), chưa liên kết với EntityManager.
  • Managed (persistent): đang trong persistence context. Thay đổi field → tự động sync xuống DB khi flush (dirty checking).
  • Detached: từng managed nhưng context đã đóng.
  • Removed: đã đánh dấu xóa, sẽ xóa khi flush.

Lợi ích:

  • Identity map: 1 row trong DB chỉ map 1 object → em.find(User.class, 1L) 2 lần trong cùng transaction chỉ query 1 lần.
  • Dirty checking: thay đổi field managed entity → tự UPDATE khi commit.
  • Write-behind: gom nhiều thay đổi, flush 1 lần.
Đây là lý do @Transactional quan trọng — không có transaction, mỗi thao tác là 1 session mới, mất tính năng cache và dirty checking.
60. @GeneratedValue strategies?

Chiến lược sinh khóa chính:

  • IDENTITY: DB auto-increment (MySQL, SQL Server). Đơn giản nhưng không hỗ trợ batch insert.
  • SEQUENCE: dùng sequence của DB (PostgreSQL, Oracle). Hỗ trợ batch insert tốt.
  • TABLE: bảng riêng sinh ID. Portable nhưng chậm.
  • AUTO: Hibernate chọn dựa trên dialect.
@Id
@GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "user_seq")
@SequenceGenerator(name = "user_seq", sequenceName = "users_id_seq", allocationSize = 50)
private Long id;

Khuyến nghị: dùng SEQUENCE với allocationSize = 50 (giảm round-trip DB). Với MySQL 8+ vẫn dùng IDENTITY là chấp nhận được.

61. Mapping quan hệ?

Các annotation quan hệ:

  • @OneToMany / @ManyToOne: quan hệ 1-N. Phổ biến nhất.
  • @OneToOne: 1-1, ví dụ User ↔ Profile.
  • @ManyToMany: N-N, cần bảng trung gian. Ít dùng vì khó kiểm soát.
@Entity
public class User {
  @Id @GeneratedValue Long id;

  @OneToMany(mappedBy = "user", cascade = CascadeType.ALL, orphanRemoval = true)
  private List<Order> orders = new ArrayList<>();
}

@Entity
public class Order {
  @Id @GeneratedValue Long id;

  @ManyToOne(fetch = FetchType.LAZY)
  @JoinColumn(name = "user_id", nullable = false)
  private User user;
}

Quan trọng:

  • mappedBy chỉ ra phía nào không sở hữu FK — luôn đặt ở phía @OneToMany.
  • Phía @ManyToOne mới là owner, có @JoinColumn.
  • cascade: thao tác trên cha → ảnh hưởng con.
  • orphanRemoval = true: xóa con khỏi collection cha → xóa con khỏi DB.
62. Cascade types? LAZY vs EAGER?

Cascade: định nghĩa propagation của các operation từ entity cha sang con.

  • PERSIST: khi persist cha → persist con.
  • MERGE: khi merge cha → merge con.
  • REMOVE: khi xóa cha → xóa con.
  • REFRESH, DETACH, ALL.

Khuyến nghị: chỉ dùng cascade khi quan hệ thực sự "cha-con" (composite).

FetchType:

  • LAZY: load khi truy cập (proxy). Mặc định cho @OneToMany, @ManyToMany.
  • EAGER: load ngay khi load cha. Mặc định cho @ManyToOne, @OneToOne.

Khuyến nghị: đặt LAZY cho tất cả quan hệ, và dùng JOIN FETCH / @EntityGraph khi cần.

Lazy loading chỉ hoạt động khi EntityManager còn mở (trong transaction). Nếu truy cập lazy field ngoài transaction → LazyInitializationException.
63. N+1 query là gì?

N+1: khi bạn query N entity cha, mỗi lần truy cập quan hệ con lại phát sinh 1 query mới → tổng 1 + N query.

List<User> users = userRepo.findAll(); // 1 query
for (User u : users) {
  System.out.println(u.getOrders().size()); // mỗi lần 1 query → N query
}

Cách phát hiện: bật log SQL của Hibernate:

spring.jpa.show-sql=true
logging.level.org.hibernate.SQL=DEBUG

Cách fix:

  1. JOIN FETCH trong JPQL: @Query("SELECT u FROM User u JOIN FETCH u.orders WHERE u.id = :id").
  2. @EntityGraph(attributePaths = "orders").
  3. @BatchSize(size = 20): Hibernate batch-in nhiều ID trong 1 query.
  4. Projection / DTO query: chỉ select field cần thiết.
Nếu dùng JOIN FETCH với @OneToMany → phải DISTINCT để tránh duplicate cha.
64. @Transactional?

Cách hoạt động: Spring dùng AOP proxy bao quanh method. Khi vào → begin, khi ra → commit, khi exception → rollback.

Propagation (lan truyền transaction):

  • REQUIRED (mặc định): dùng transaction hiện có, nếu không có thì tạo mới.
  • REQUIRES_NEW: luôn tạo transaction mới, tạm dừng transaction hiện tại.
  • NESTED: transaction con với savepoint.
  • MANDATORY: bắt buộc phải có transaction sẵn.
  • NEVER, SUPPORTS, NOT_SUPPORTED.

Isolation: READ_UNCOMMITTED, READ_COMMITTED, REPEATABLE_READ, SERIALIZABLE.

Rollback: mặc định chỉ rollback với RuntimeException và Error. Muốn rollback với checked exception → @Transactional(rollbackFor = Exception.class).

readOnly = true: tối ưu — Hibernate skip dirty checking. Nên dùng cho query method.

Pitfall lớn: self-invocation. Gọi method @Transactional từ chính class đó (this.method()) sẽ không qua proxy → không có transaction. Fix: tách ra class khác, hoặc dùng AopContext.currentProxy().
65. Optimistic vs Pessimistic lock?

Optimistic lock: giả định ít conflict. Dùng @Version:

@Entity
public class Product {
  @Id Long id;
  private int quantity;
  @Version private Long version;
}

Mỗi UPDATE thêm WHERE version = ?, đồng thời tăng version. Nếu version đã thay đổi → OptimisticLockException → ứng dụng phải retry hoặc báo lỗi.

Pessimistic lock: khóa DB ngay khi đọc:

@Lock(LockModeType.PESSIMISTIC_WRITE)
@Query("SELECT p FROM Product p WHERE p.id = :id")
Product findByIdForUpdate(Long id);
// sinh SQL: SELECT ... FOR UPDATE

Lock giữ đến hết transaction. Thread khác chờ lock.

Chọn khi nào:

  • Optimistic: ít conflict, transaction ngắn, web app đa số.
  • Pessimistic: conflict cao (bán vé, trừ kho liên tục).
66. Connection pool? HikariCP?

Connection pool: giữ sẵn N connection, tái sử dụng. Tránh overhead tạo connection mới mỗi request (mất 50-100ms).

HikariCP là pool mặc định của Spring Boot 2+, nhanh nhất hiện nay.

spring.datasource.hikari:
  maximum-pool-size: 10
  minimum-idle: 5
  connection-timeout: 30000
  idle-timeout: 600000
  max-lifetime: 1800000

Công thức chọn pool size (từ Hikari docs): connections = ((core_count * 2) + effective_spindle_count). Ví dụ 4 core → ~10 connection. Không phải càng lớn càng tốt.

Cảnh báo: nếu app block lâu (query chậm), connection bị giữ → request khác chờ → timeout. Monitor pool usage qua Actuator (/actuator/metrics/hikaricp.connections.active).

67. Pagination, sorting? 
// Page (có total count)
Pageable pageable = PageRequest.of(0, 10, Sort.by("createdAt").descending());
Page<User> page = userRepo.findAll(pageable);

page.getContent();       // list
page.getTotalElements(); // tổng số
page.getTotalPages();    // số trang

// Slice (không count — hiệu quả hơn)
Slice<User> slice = userRepo.findByStatus(Status.ACTIVE, pageable);
slice.hasNext();

Controller:

@GetMapping
public Page<UserDto> list(
    @PageableDefault(size = 10, sort = "id", direction = DESC) Pageable pageable) {
  return userService.findAll(pageable);
}

Spring Boot tự bind ?page=0&size=10&sort=id,desc vào Pageable.

Với dataset lớn, Page dùng COUNT(*) có thể chậm. Dùng Slice hoặc keyset pagination (WHERE id > lastId LIMIT n).
68. ACID? Isolation levels?

ACID:

  • Atomicity: transaction all-or-nothing.
  • Consistency: dữ liệu từ trạng thái hợp lệ này sang trạng thái hợp lệ khác.
  • Isolation: transaction không thấy thay đổi chưa commit của transaction khác.
  • Durability: sau khi commit, dữ liệu tồn tại kể cả khi crash.

Isolation levels (thấp → cao):

LevelDirty ReadNon-RepeatablePhantom
READ_UNCOMMITTED✓✓✓
READ_COMMITTED✗✓✓
REPEATABLE_READ✗✗✓
SERIALIZABLE✗✗✗

Ví dụ:

  • Dirty read: đọc dữ liệu chưa commit của transaction khác.
  • Non-repeatable: đọc cùng row 2 lần được 2 giá trị khác nhau.
  • Phantom: query lần 1 có N row, lần 2 có N+1.
69. SQL vs NoSQL?

SQL (RDBMS): MySQL, PostgreSQL, Oracle, SQL Server.

  • Schema cố định, ACID đầy đủ, JOIN mạnh, transaction.
  • Vertical scale (tăng CPU/RAM) hoặc read replica.
  • Dùng khi: dữ liệu có cấu trúc, quan hệ, cần consistency cao (banking, ERP).

NoSQL:

  • Document: MongoDB — JSON document, flexible schema.
  • Key-value: Redis — cache, session.
  • Column-family: Cassandra, HBase — write-heavy, time-series.
  • Graph: Neo4j — quan hệ phức tạp.

Đặc điểm: schema linh hoạt, horizontal scale, thường eventual consistency (BASE).

Chọn: Cần transaction ACID, quan hệ phức tạp → SQL. Cần scale lớn, write-heavy, schema thay đổi → NoSQL.

5. Microservices & DevOps

70. Monolith vs Microservices?

Monolith:

  • 1 codebase, 1 deployment unit.
  • Ưu: đơn giản, dễ debug, transaction ACID dễ, deploy 1 lần.
  • Nhược: scale toàn bộ app, coupling cao, 1 bug có thể sập cả hệ, deploy chậm khi lớn.

Microservices:

  • Nhiều service độc lập, mỗi service 1 DB riêng, giao tiếp qua API/message.
  • Ưu: scale độc lập, deploy độc lập, mỗi team tự chủ tech stack.
  • Nhược: phức tạp vận hành, distributed transaction (Saga), monitoring, debugging khó.

Nguyên tắc thiết kế: chia theo business capability (DDD bounded context), không chia theo layer. Ví dụ: User Service, Order Service, Payment Service.

Với dự án nhỏ/team nhỏ → bắt đầu bằng modular monolith. Chỉ tách microservices khi thực sự cần scale team/service.
71. RESTful API? HTTP status codes?

REST (Representational State Transfer) — kiến trúc với các đặc điểm:

  • Stateless: server không lưu state client; mỗi request độc lập.
  • Resource-based: URL là danh từ số nhiều (/users, /orders/123).
  • HTTP verbs: GET (đọc), POST (tạo), PUT (thay thế toàn bộ), PATCH (cập nhật một phần), DELETE (xóa).
  • Idempotent: GET/PUT/DELETE idempotent; POST thì không.

Status codes:

  • 2xx: 200 OK, 201 Created, 204 No Content.
  • 3xx: 301 Moved, 304 Not Modified.
  • 4xx: 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 409 Conflict, 422 Unprocessable Entity, 429 Too Many Requests.
  • 5xx: 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable, 504 Gateway Timeout.
Đừng nhầm 401 vs 403: 401 = chưa authentication; 403 = đã authentication nhưng thiếu quyền.
72. API Gateway, Service Discovery, Config Server?
  • API Gateway (Spring Cloud Gateway, Kong, Nginx): điểm vào duy nhất cho client. Nhiệm vụ: routing, authentication, rate limiting, CORS, load balancing. Client chỉ cần biết gateway.
  • Service Discovery (Eureka, Consul, k8s Service): service tự động đăng ký địa chỉ khi khởi động; client lookup để gọi.
  • Config Server (Spring Cloud Config, Consul KV): quản lý config tập trung (thường từ Git).
  • Load Balancer: phân tải giữa các instance (Ribbon, Spring Cloud LoadBalancer, k8s Service).

Spring Cloud cung cấp tích hợp cho tất cả. Với Kubernetes, Service Discovery + ConfigMap/Secret đã có sẵn → ít dùng Eureka hơn.

73. Circuit Breaker?

Vấn đề: nếu service A gọi service B đang chậm/down, A sẽ chờ timeout → thread pool cạn → A cũng down → cascade failure.

Circuit Breaker giải quyết bằng 3 trạng thái:

  • CLOSED: bình thường, cho request qua. Đếm failure.
  • OPEN: khi failure vượt ngưỡng → block hết request, trả fallback ngay. Sau timeout → HALF_OPEN.
  • HALF_OPEN: cho 1 số request thử. Thành công → CLOSED; fail → OPEN lại.
@CircuitBreaker(name = "inventory", fallbackMethod = "fallback")
public Inventory checkInventory(Long productId) {
  return inventoryClient.get(productId);
}

Resilience4j là thư viện hiện đại (thay Hystrix đã ngừng phát triển).

74. Kafka vs RabbitMQ?

Kafka:

  • Distributed log, partition-based, thứ tự trong partition.
  • Message được lưu trên disk có thể replay.
  • Throughput rất cao (hàng triệu msg/s).
  • Pull model — consumer chủ động pull.
  • Dùng cho: event streaming, log aggregation, event sourcing.

RabbitMQ:

  • Message broker truyền thống, push model.
  • Routing linh hoạt: direct, topic, fanout, headers.
  • Message bị xóa sau khi consumer ack (không replay).
  • Dùng cho: task queue, RPC, microservice async đơn giản.

Chọn: cần streaming/replay/throughput → Kafka. Cần routing phức tạp, task queue đơn giản → RabbitMQ.

75. Distributed transaction? Saga?

Vấn đề: microservices mỗi service có DB riêng → không thể dùng 1 transaction ACID xuyên service.

Saga pattern: chia business transaction thành nhiều local transaction. Mỗi bước thành công → next. Nếu bước N fail → chạy compensating transaction cho N-1 bước trước đó.

2 cách triển khai:

  • Choreography: các service phát event, service khác lắng nghe. Không có trung tâm điều phối. Đơn giản cho flow nhỏ.
  • Orchestration: có 1 orchestrator (Temporal, Camunda) điều phối. Rõ ràng, dễ debug.

Ví dụ: Order → Payment → Inventory. Nếu Inventory fail → Payment phải refund, Order cancel.

Saga đảm bảo eventual consistency, không phải ACID. Cần thiết kế idempotent cho retry.

    return UserMapper.toDto(u); // dirty checking
  }

    if (!repo.existsById(id)) throw new ResourceNotFoundException("User", id);
    repo.deleteById(id);
  }

@RestControllerAdvice

// JwtFilter
@Component @RequiredArgsConstructor
public class JwtAuthenticationFilter extends OncePerRequestFilter {
  private final JwtService jwtService;
  private final UserDetailsService uds;

  @Override
  protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res,
                                  FilterChain chain) throws IOException, ServletException {
    String header = req.getHeader("Authorization");
    if (header == null || !header.startsWith("Bearer ")) {
      chain.doFilter(req, res); return;
    }
    String token = header.substring(7);
    try {
      String username = jwtService.extractUsername(token);
      if (username != null && SecurityContextHolder.getContext().getAuthentication() == null) {
        UserDetails user = uds.loadUserByUsername(username);
        if (jwtService.isValid(token, user)) {
          UsernamePasswordAuthenticationToken auth =
              new UsernamePasswordAuthenticationToken(user, null, user.getAuthorities());
          SecurityContextHolder.getContext().setAuthentication(auth);
        }
      }
    } catch (JwtException e) { /* 401 */ }
    chain.doFilter(req, res);
  }
}

@PostMapping(value = "/upload", consumes = MULTIPART_FORM_DATA_VALUE)
public ResponseEntity<FileResponse> upload(
    @RequestParam("file") MultipartFile file,
    @RequestParam(required = false) String folder) throws IOException {

  if (file.isEmpty())
    throw new BadRequestException("File rỗng");
  if (file.getSize() > 5 * 1024 * 1024)
    throw new BadRequestException("File > 5MB");

  String contentType = file.getContentType();
  Set<String> allowed = Set.of("image/png", "image/jpeg", "application/pdf");
  if (!allowed.contains(contentType))
    throw new BadRequestException("Loại file không được hỗ trợ");

  String ext = StringUtils.getFilenameExtension(file.getOriginalFilename());
  String fileName = UUID.randomUUID() + "." + ext;
  Path target = Paths.get("uploads", folder != null ? folder : "default").resolve(fileName);
  Files.createDirectories(target.getParent());
  file.transferTo(target.toAbsolutePath());

  return ResponseEntity.ok(new FileResponse(fileName, "/files/" + fileName));
}

  • Đóng góp: chủ động thiết kế module, review code cho junior, viết technical doc, chia sẻ knowledge trong team.
  • Cá nhân: đọc sách (Effective Java, Designing Data-Intensive Applications), tham gia cộng đồng.

Tránh nói: "Em muốn làm manager" nếu apply vị trí technical, hoặc "Em muốn học X" nhưng X không liên quan vị trí.

98. Câu hỏi cho nhà tuyển dụng?

Nên hỏi 2-3 câu, thể hiện sự quan tâm thật:

  • Về công việc: "Team em sẽ làm dự án gì trong 6 tháng tới? Tech stack cụ thể ra sao?"
  • Về quy trình: "Team đang dùng quy trình nào? Có review code, có CI/CD không?"
  • Về phát triển: "Công ty có budget học tập, tham gia conference không? Lộ trình thăng tiến ra sao?"
  • Về văn hóa: "Điều gì khiến anh/chị thích làm ở đây nhất? Team xử lý conflict thế nào?"
  • Về thách thức: "Hiện tại team đang gặp khó khăn gì về technical mà em có thể giúp?"

Không nên hỏi ngay: lương, nghỉ phép, OT (để dành cho HR round sau).
